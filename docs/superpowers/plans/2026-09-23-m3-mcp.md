# M3 · MCP 双端 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** bill/work-item 两个 MCP server(Spring Boot,streamable-http)+ MCP 客户端管理器(有界重连 + 熔断 + 结构化降级)+ web 层 MCP 模式(owner 身份注入、commit_issue 双闸审批、审批卡片工单信息补全)。

**Architecture:** 模块重构先行 —— 新建 `billguard-domain`(账单域 + 全部 PG 存储 + 工单域 + 技能源),使 MCP server 不拖拽 web 应用;新建 `billguard-mcp`(一个模块、两个 Boot 应用,`--spring.profiles.active=bill|work-item` 选择);web 按环境变量切换本地/MCP 工具源。依赖方向:`web → domain ← mcp`,`domain → agent-runtime`。

**Tech Stack:** MCP Java SDK `io.modelcontextprotocol.sdk:mcp:0.18.4` + `mcp-spring-webmvc`(server 传输)/ 客户端内置 streamable-http 传输;其余沿用 M1/M2。

**Spec:** `docs/superpowers/specs/2026-09-22-java-agent-runtime-design.md` §8(MCP 层)与 §5.4-3(熔断状态机)

## Global Constraints(M1/M2 沿用,新增)

- Python 参考源:`mcp_runtime.py` / `mcp_servers/bill_server.py` / `mcp_servers/work_item_server.py` / `work_items.py` / `storage_pg.py`(PGWorkItemStore)/ `web.py`(inject_owner_identity、_decide_approval_locked 双闸、_enrich_approval)
- **工具目录与描述逐字**:bill server 6 工具(aggregate/query/compare_periods/detect_anomalies/get_samples/update_status)与 work-item server 4 工具(list_issues/get_issue/prepare_issue/commit_issue)的 name/description/参数 schema 对齐;`update_status` meta `{risk_level: high_write, requires_approval: true, policy_reason: "Updates bill transaction workflow state"}`;`prepare_issue` low_write;`commit_issue` high_write
- **两 server 均暴露**:`/health`(GET {"ok":true},不触存储)、3 资源(bill://schema|categories|metric-definitions;work-items://schema)、2 prompt(investigate-bill-anomaly / monthly-guard-report;create-bill-action-item);instructions 逐字
- **approve 永不作为 MCP 工具暴露**(通道外人工决策)
- **工单状态机**:`pending → approved/rejected → consumed`(decide 条件 UPDATE 恰好一次 + 过期置 expired);commit:`FOR UPDATE` 行锁 + consumed 幂等回放 `{created, idempotent_replay}`;ISS-NNNN 由 issues.BIGSERIAL 映射;prepare 30 分钟过期,`next_step` 文案逐字(`prepare_issue_next_step`)
- **熔断状态机**(spec §5.4-3):closed →(连接类失败,重连退避 1s/2s/4s × 3 耗尽)→ open(60s 快速失败)→ half_open(单探)→ closed;recovering 标志期间并发调用快速失败;half_open 过期兜底 30s;熔断拒绝 → `{"error":..., "degraded":true}`(引擎侧高写降级记失败 —— M1 已实现)
- **连接类错误判定**:沿 `getCause()` 显式因果链(suppressed 不参与),类型白名单(IOException 家族 / TimeoutException / MCP SDK 传输异常)+ 报文关键词(connection closed/refused/reset、timed out while waiting for response 等,清单逐字);HTTP 408/429 按可重试,其余 4xx/5xx 原样上抛
- **owner 注入**(web.py inject_owner_identity):`bill.*` 工具 handler 包装 —— 参数按 schema 白名单过滤、`owner`(与已声明的 `operator`)强制覆盖为服务端身份;schema 的 properties/required 移除身份键(模型不可见);非 bill.* 透传
- **注册名**:`{server}.{tool}`(bill.aggregate / work-items.commit_issue);描述前缀 `[MCP:{server}] `
- **远端策略推导**:meta.risk_level 优先;缺省按 annotations(readOnlyHint→read,destructiveHint→high_write),未知写默认 high_write;requires_approval 缺省 = risk==high_write
- MCP 模式环境变量:`BILLGUARD_BILL_MCP_URL` / `BILLGUARD_WORK_ITEM_MCP_URL`(两者与 PG/Redis 同设才启用,缺一启动退出 —— 对齐 Python 语义);mcp server 侧 `BILLGUARD_PG_URL/USER/PASSWORD` 复用
- 每任务 TDD + commit;Docker 运行中

## 附录:SDK 0.18.4 API 实测(Task 0 spike 结论)

- **依赖坐标**:`io.modelcontextprotocol.sdk:mcp` 是聚合 POM(空 jar);实件 = `mcp-core`(协议/Server/Client/schema)+ `client-jdk-http-client`(JDK HttpClient 流式传输)+ `mcp-spring-webmvc`(WebMVC 传输 Provider)
- **Server(无状态,对齐 Python stateless_http=True)**:`McpServer.sync(WebMvcStatelessServerTransport)` → `StatelessSyncSpecification`(`.serverInfo(new Implementation(name, version))`、`.instructions(...)`、`.tools(McpStatelessServerFeatures.SyncToolSpecification...)`、`.resources(...)`、`.prompts(...)`)→ `build()` 得 `McpSyncServer`;传输的 `getRouterFunction()` 注册为 `RouterFunction<ServerResponse>` Bean 暴露 `/mcp`
- **工具定义**:`new Tool(name, title, description, JsonSchema(inputSchema), outputSchema, ToolAnnotations, meta)` —— **meta 即 Map**(risk_level/requires_approval/policy_reason 放这里,client 优先读);ToolAnnotations 六参 record(title, readOnlyHint, destructiveHint, idempotentHint, openWorldHint, …)
- **工具结果**:`new CallToolResult(List<Content>, isError, structuredContent, meta)` 四参构造带 **structuredContent**(对齐 Python structured_output=True);简单文本用 `new CallToolResult(String, Boolean)`
- **Client**:`McpClient.sync(HttpClientStreamableHttpTransport.builder(url).endpoint("/mcp").build()).requestTimeout(Duration).build()` → `McpSyncClient.initialize()/listTools()/listTools(cursor)/callTool(new CallToolRequest(name, args))`;分页靠 nextCursor 逐页拉
- **/health 自定义路由**:普通 `@GetMapping` 与 MCP RouterFunction 并存无冲突
