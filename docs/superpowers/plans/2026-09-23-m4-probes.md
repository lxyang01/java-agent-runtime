# M4 · 证明体系(25 条对抗探针)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Python 版 25 条对抗探针(adv-001..adv-025)平移为 Java `AdversarialEvaluator`,在真实 PG/Redis(Testcontainers)上全量运行,输出与 Python 同构的报告结构;**验收 = 25/25 通过**。

**Architecture:** 新模块 `billguard-eval`(依赖 domain + web 测试件 + runtime);探针与 Python 一一对应,分四批落地:引擎级(001-018)、Web/身份级(019/021/022 假管理器)、HTTP 级(024/025 真实 MockMvc)、运行器与报告。每条探针 = 一个 `Probe` 方法,复用 Java 侧既有构件(ScriptedLlm=QueueLLM、AgentRuntime、PgApprovalStore、BillGuardFacade、MockMvc)。

**Tech Stack:** JUnit5 + Testcontainers(PG/Redis)+ MockMvc(web 测试件)。

**Spec:** spec §1「安全与审计行为可证等价:25 条对抗探针全量平移并通过」

## Global Constraints

- Python 参考源:`adversarial_evaluation.py`(逐探针对照);探针的 id/类别/严重度/标题/攻击描述/期望/修复建议**逐字**进报告
- 报告结构对齐:`{schema_version:1, evaluation_type:"adversarial", benchmark:"billguard-adversarial-v1", evaluated_at, dataset_size, metrics{total,passed,failed,defense_rate,critical_failures,high_failures,probe_errors,latency_ms}, categories{…defense_rate}, results[{id,category,severity,title,attack,expected,passed,observed,evidence,remediation,probe_error,latency_ms}], scope_note}`(逐字 scope_note)
- 夹具重置对齐 `_reset_fixtures`:12 张业务表 DELETE + 夹具用户(alice/mallory)删除 + Redis 扫 `lock:session:*`/`llm:slots`;024/025 自产 login/auth 键探针内自清
- 工具名 `feedback_samples`(adv-006/007 legacy 别名)与 `safe.read`/`hidden.write`/`danger.write` 保持 —— contracts 别名组与白名单语义依赖这些名字
- `_numeric_grounding`(adv-015 离线分)可省略 —— Python 只把它放进 evidence,`protected` 判定不依赖它
- 每批 TDD:探针先红(断言按 Python 期望)→ 修 runtime/web 缺口(若有)→ 绿 → commit
